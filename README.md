# SEN 鑑定安置前端互動原型

以假資料展示梯次設定、流程控制與學生案件操作。不連接正式 SEN 系統；請勿輸入真實學生個資。

## 執行

使用 Node.js 22 或以上（已以 Node.js 24 驗證），無外部依賴，不需執行 npm install。

```sh
cd /workspace/SEN-Prototype
npm start
```

預設使用 3000 埠，可用 `PORT` 調整。以瀏覽器開啟服務即可使用。`npm test` 執行業務狀態測試。

## 示範流程

1. 在「梯次管理 → 梯次設定」完成提報區間，首次會自動選用並開放派案與填寫評估報告。取消後重新修改區間不會再次覆蓋設定。
2. 在「各流程設定」分別調整選用、手動開放或自動日期區間。
3. 切換至案件管理及不同角色，檢視操作權限與各階段狀態。學校端可於提報期間新增假資料；管理端可派案；評估與審查人員可記錄示範內容。
4. 展開情境測試工具，載入提報開放、派案關閉、自動審查或核定資料未齊備情境，並改變模擬時間測試區間邊界。載入情境需確認替換目前假資料。
5. 重新整理會保留梯次設定及案件內容；模擬時間及角色不會保留。「重設假資料」可清除目前示範內容。

## 規則與待確認事項

- 文號及核定日期非建立梯次必填，但為結果公告／學校接收的前置檢核。
- 鑑輔會審查結果及結果公告／學校接收為必填流程，不可取消；其開放時機及控制方式待確認，因此操作保持停用。補齊核定資料不會自行開放。
- 角色配置僅為展示假設：管理端派案、評估人員填寫報告、審查人員審查、學校端提報與接收。正式權限矩陣待確認。
- 案件階段先後、重複操作、撤案／抽回／陳述意見細則待確認，未加入推測的業務限制。後三項僅展示流程開放狀態。
- 教育階段與年級為獨立多選示範，實際對應關係與申請項目、身分選項待確認。
- 時間以臺北時區、分鐘精度計算，起訖時間皆包含。畫面每分鐘重新檢核開放狀態，執行操作時亦會重新檢核。
- 設定即時套用並以瀏覽器 localStorage 保存。無後端、無身分驗證，角色切換不構成正式授權機制。

## 部署至 GitHub Pages

已提供 `.github/workflows/deploy-pages.yml`。不需部署金鑰、GitHub Token 或額外套件；工作流程使用 GitHub 內建的授權。

首次部署：

1. 將這次新增及修改的專案檔案提交並推送至 GitHub 的 `main` 分支。只有雲端工作區有檔案時，GitHub 不會收到變更。
2. 到 GitHub 儲存庫 **Settings → Pages → Build and deployment**，把 **Source** 設為 **GitHub Actions**。若無法使用 Pages，需先確認儲存庫可見性與帳號方案支援。
3. 到 **Actions → Deploy prototype to GitHub Pages → Run workflow**，選取 `main` 後執行。之後推送至 `main` 時會自動部署。
4. 等待 `build` 與 `deploy` 都顯示成功，在部署結果或 **Settings → Pages** 取得網站網址。預期網址為 `https://yingtzu35.github.io/SEN-Prototype/`，以 GitHub 實際顯示為準。

工作流程先執行規則測試與語法檢查，再執行 `npm run build`，只將 `dist/` 中的前端資源上傳。網站使用相對路徑，支援 `/SEN-Prototype/` 專案路徑；不需要在 GitHub 上執行 `npm start`。

此設定尚不代表已發布網站，必須先推送程式碼並完成一次成功部署。GitHub Pages 網站通常可公開存取；原型僅供假資料展示，無登入權限防護。資料仍各自儲存在使用者瀏覽器，並不跨裝置同步；本機開發網址的資料也不會自動搬至 Pages 網址。
